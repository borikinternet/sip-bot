## Текущее состояние

- Проект — демонстрационный, рассчитан на **один одновременный SIP-звонок**. Основной Python-runtime — CPython 3.14.7t без GIL; SIP/media — PJSUA2/PJMEDIA и PCMU; ASR — faster-whisper large-v3; LLM — Qwen3.5-9B через локальную Ollama; embeddings — embeddinggemma; TTS — XTTS-v2. Критичные native-модули используют сохранённые no-GIL патчи. Версии, исходники, хеши и границы проверки перечислены в [журнале развёртывания](artifacts/workshops/sip-bot-deployment-20260929/execution-journal.md), а не дублируются здесь.
- Исходный код на момент подготовки этого handoff уже включает журнал мастер-класса, конфигурации стенда и исправления холодного запуска. Старые хеши коммитов не приводятся: история Git обезличена и переписана.
- Для чистого повтора 29 сентября создан WSL-дистрибутив `SIP-Bot-Workshop-20260929` (Ubuntu 24.04.5) в `D:\WSL\SIP-Bot-Workshop-20260929`. Внутри него Debian Bookworm в `systemd-nspawn` содержит пакетный FreeSWITCH и две очереди: `7100` для бота `1002`, `7000` для операторов. Docker и прежние WSL-дистрибутивы не менялись.
- Локальные страховочные копии весов и подготовленного native runtime лежат в `D:\sip-bot-workshop-cache\20260929`. Они **не входят в Git**. Команды получения исходных ресурсов из Интернета с версиями и хешами записаны в журнале вместо команд копирования, но их сетевое исполнение и полная пересборка patched runtime в этом прогоне по условию задачи не проводились.

## Что фактически проверено

- Контрольный Baresip-звонок на `7100` прошёл через FreeSWITCH с PCMU/RTP: бот распознал несколько фраз, обратился к базовому RAG-индексу, озвучил ответы и сформировал отчёт. [Отчёт](artifacts/workshops/sip-bot-deployment-20260929/control-call-report.md) и [текстовый контекст](artifacts/workshops/sip-bot-deployment-20260929/control-call-conversation.jsonl) опубликованы; стерео-WAV остался локальным, поскольку `artifacts/**/*.wav` исключён `.gitignore`.
- Базовый корпус этого повтора — о технологиях голосовых ассистентов, **не** о ценах на услуги и не научная Википедия. Отказы отвечать на вопросы вне корпуса в контрольном звонке отражены в диагностике RAG; это не доказательство неисправности SIP или TTS.
- Локальный HTTPS backend вернул `200`, WSS handshake — `101`; тестовая загрузка документа создала индекс и достигла `state=ready`. Полный браузерный WebRTC-аудиозвонок с новым корпусом **не проверен**. Локальный QR указывает на LAN-адрес, который с Windows-хоста при текущей WSL-сети не открывался; адрес для аудитории надо проверить заново.
- На основном checkout проверка `tests/unit tests/contract demo-web/tests` дала `292 passed` (предупреждения aiohttp); реестр документов был целостным. В локальном клоне стенда один тест публичного URL ожидаемо конфликтует с заменённым на адрес стенда `demo-config.js`.

## Не выдавать за подтверждённое

1. `transfer_completed / operator_connected` в отчёте **не подтверждает соединение с человеком**. Live runner пока использует `FakeOperator`; `OPERATOR_TARGET` указывает на `sip:operator@127.0.0.1:5090`, а живая очередь FreeSWITCH — `7000`. Требуется отдельная проверка фактического SIP REFER и результата до `1001`.
2. Публичное `https://demo.libnas.ru/` и его backend/WSS не проверялись в прогоне 29 сентября. Исторические проверки и тогдашние ограничения описаны в сохранённом [handoff публичного маршрута](docs/handoffs/HANDOFF-2026-09-25-public-route.md); не считать локальный контрольный звонок проверкой публичного сайта.
3. Зафиксированные сетевые команды скачивания моделей и исходников **не исполнялись**. Повторяемость из локальных проверенных архивов и полностью автономное воспроизведение только из Интернета — разные утверждения.
4. Настройки IP, SIP-пароль и самоподписанный сертификат в учебном стенде являются лабораторными. Их нельзя переносить на доступный извне сервер без пересмотра.
