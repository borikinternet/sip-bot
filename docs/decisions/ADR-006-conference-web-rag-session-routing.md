# ADR-006: conference web-demo с caller ID и session-scoped RAG

Статус: `accepted`

## Контекст

Для конференционной демонстрации нужен отдельный web-интерфейс, который позволяет загрузить небольшой
`Markdown`/`TXT`-корпус, дождаться подготовки RAG и позвонить в существующую SIP-очередь FreeSWITCH.
Демонстрационный контур рассчитан на закрытую сеть, не требует авторизации и сохраняет односессионное
ограничение SIP-бота.

Нужно связать web-сессию и входящий SIP-звонок, не передавая аудио через web-backend и не создавая вторую
очередь вызовов. Существующая очередь `mod_callcenter` остаётся владельцем порядка звонков.

## Решение

- На открытии страницы backend назначает временные `session_id` и уникальный `caller_id`.
- WebSocket heartbeat подтверждает, что ожидающая web-сессия ещё жива.
- Загрузка корпуса создаёт session-scoped подготовленный RAG-артефакт с metadata, chunks и embeddings.
- Кнопка звонка активируется только после успешной публикации артефакта.
- Browser SIP-клиент звонит с назначенным caller ID в SIP URI user-part на существующую очередь `mod_callcenter`.
- PJSUA2 извлекает и нормализует URI user-part caller ID из входящего вызова и использует его для выбора корпуса.
- Текущий dialplan отвечает caller leg до `callcenter`; пользователь получает `200 OK` при входе в очередь и слышит
  queue `moh-sound` до подключения агента.
- На отдельной bot agent leg `180 Ringing` отправляется до загрузки выбранного индекса; затем в пределах `15 s`
  отправляется `200 OK` только после готовности индекса.
- После terminal SIP event call-scoped корпус удаляется.
- При отсутствии живого пользовательского mapping бот использует базовый RAG и актуальное generic/topic greeting,
  а не устаревший пользовательский корпус.
- Во время активного вызова heartbeat не является условием существования корпуса: корпус живёт до завершения SIP-сессии.

## Рассмотренные альтернативы

1. Запуск отдельного bot-инстанса на каждого пользователя — отклонено: для конференционного demo достаточно
   последовательной обработки существующей односессионной системой.
2. Вторая очередь вызовов в web-backend — отклонено: очередь уже принадлежит FreeSWITCH `mod_callcenter`.
3. Передача PCM или текста через web-сокет — отклонено: web-сокет используется только для статуса и heartbeat.
4. Глобальная замена активного RAG во время звонка — отклонено: индекс выбирается для конкретной call-сессии.
5. Обязательная авторизация и production secret management — отложено за границы conference demo.

## Последствия

- Backend и bot runtime должны видеть общий локальный registry `caller_id → prepared index` через атомарно публикуемый
  каталог на одной машине/ОС.
- В SIP-событии PJSUA2 должен быть доступен нормализованный caller ID.
- Readiness gate становится call-scoped для RAG load на bot agent leg, сохраняя существующую схему `180 → readiness → 200`;
  caller leg остаётся отвеченным и получает hold music от `mod_callcenter`.
- Demo backend выбирает Python `aiohttp` как один локальный HTTP/static/upload/WebSocket sidecar; точная версия и
  наличие зависимости фиксируются первым import probe.
- Публичная безопасность и защита SIP-учётных данных сознательно не являются acceptance-критериями.
- Browser WSS/DTLS-SRTP зависит от отдельной `Map-020`; эта ADR не изменяет FreeSWITCH transport baseline.
