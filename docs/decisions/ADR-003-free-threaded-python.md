# ADR-003: Приоритет free-threaded CPython и проверка совместимости зависимостей

Статус: `accepted`

## Контекст

В приложении одновременно присутствуют SIP/RTP-обработка, потоковый ASR, LLM, TTS и управление состоянием звонка. Часть VoIP- и inference-компонентов может выполняться в native-потоках. Обычный CPython с GIL ограничивает параллельное выполнение Python-кода и усложняет использование нескольких CPU-потоков внутри одного процесса.

Начиная с Python 3.13 существует free-threaded-сборка CPython, в которой GIL отключён. В Python 3.13 этот режим был экспериментальным, а с Python 3.14 получил официальный поддерживаемый статус. Однако C-расширение, не заявившее поддержку free-threading, при импорте может автоматически включить GIL обратно. Это особенно важно для SIP/RTP-обёрток, inference runtime и библиотек обработки аудио.

Для MVP достаточно стабильной free-threaded-сборки CPython не ниже 3.14. Конкретный patch/minor-релиз не является заранее заданным требованием: при execution выбирается последний доступный стабильный релиз, после чего его фактическая версия и результаты проверок записываются в evidence. Более новый стабильный free-threaded релиз допустим при прохождении тех же проверок совместимости.

## Решение

Основной процесс MVP использует последнюю доступную стабильную free-threaded-сборку CPython не ниже 3.14 (`3.14t` или более новую поддержанную ветку). Точная версия выбирается в ходе `001-B` и фиксируется как результат проверки, а не как предварительное owner-требование. Целевая среда — Ubuntu 24.04 LTS x86_64 в WSL2.

Компоненты выбираются с учётом совместимости с free-threaded-сборкой, а не только с обычным CPython. Отсутствие GIL является обязательным свойством основного процесса, но не каждого процесса системы: несовместимый native-компонент изолируется отдельным процессом с явным IPC-контрактом.

Для каждого варианта SIP/media-стека и каждой критичной зависимости выполняется отдельная проверка:

1. Интерпретатор является free-threaded-сборкой:

   ```python
   import sysconfig

   assert sysconfig.get_config_var("Py_GIL_DISABLED") == 1
   ```

2. До импорта проверяемых зависимостей GIL отключён:

   ```python
   import sys

   assert not sys._is_gil_enabled()
   ```

3. В чистом процессе импортируются прямые и критичные транзитивные зависимости.
4. После каждого импорта и после выполнения сценария с ленивыми импортами проверяется, что `sys._is_gil_enabled()` остаётся `False`.
5. Предупреждение Python об автоматическом включении GIL считается ошибкой проверки.
6. Затем выполняется минимальный smoke-тест фактического вызова, поскольку совместимость импорта не гарантирует потокобезопасность работы библиотеки.

Компонент, который включает GIL обратно в основном процессе, считается несовместимым с приоритетной конфигурацией до тех пор, пока не будет найдено одно из решений:

- версия компонента с поддержкой free-threading;
- сборка собственного адаптера с явной поддержкой free-threading;
- изоляция компонента в отдельном процессе без импорта его native-модуля в основной Python-процесс.

Обычный GIL-enabled CPython допускается только внутри такого изолированного процесса и не считается успешной проверкой основного runtime. Более новая free-threaded ветка допускается тем же execution-процессом после проверки совместимости; отдельная экспериментальная ветка не требуется заранее.

Проверка не отменяет использования очередей, блокировок и явных границ владения данными. Отключённый GIL не делает native-библиотеки или пользовательский код автоматически потокобезопасными.

## Последствия

Положительные:

- появляется возможность использовать настоящую параллельность CPU-потоков в одном Python-процессе;
- потенциально уменьшается давление на архитектуру из-за необходимости обходить GIL;
- совместимость native-зависимостей становится явным техническим критерием;
- отдельный процесс остаётся контролируемым способом изолировать несовместимый компонент.

Отрицательные:

- доступных готовых wheels и совместимых Python-обёрток меньше;
- часть зависимостей потребуется собирать самостоятельно;
- free-threaded build может иметь повышенный расход памяти и небольшую потерю однопоточной производительности;
- понадобится отдельный тест импорта и smoke-тест для каждого варианта стека;
- free-threaded CPython не устраняет проблемы гонок, блокировок и корректного управления временем жизни объектов.

## Применение к кандидатам VoIP-стека

- Для **PJSUA2** проверяется совместимость SWIG-модуля и всех его Python-native зависимостей.
- Для **Sofia-SIP + aiortp** отдельно проверяются Python-адаптер Sofia и зависимости `aiortp`; сам Python-код не считается достаточным доказательством совместимости.
- Для **Baresip отдельным процессом** проверяется только Python-клиент управления и аудиомост. Native-код Baresip не импортируется в основной процесс, поэтому не может включить GIL в нём.

## Базовая версия и экспериментальная ветка

```text
Основной runtime: последняя стабильная free-threaded сборка CPython >= 3.14, выбранная в execution
Целевая ОС: Ubuntu 24.04 LTS x86_64
Основной процесс: GIL disabled
Несовместимые native-компоненты: отдельный процесс
Точная версия: фиксируется в runtime evidence после выбора stable-релиза
```

Проверка свободнопоточной сборки должна использовать `sysconfig.get_config_var("Py_GIL_DISABLED")`, а проверка фактического состояния GIL — `sys._is_gil_enabled()`. После импорта всех прямых и лениво загружаемых критичных зависимостей значение `sys._is_gil_enabled()` должно оставаться `False`; автоматическое включение GIL считается отрицательным результатом для основного процесса.
