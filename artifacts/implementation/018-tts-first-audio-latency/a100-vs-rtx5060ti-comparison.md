# A100 и RTX 5060 Ti: сравнительный прогон SIP-бота

Дата прогона RTX: 2026-09-23.

## Условия сравнения

- Сервер: NVIDIA A100-SXM4-40GB, 40960 MiB, driver 595.91.07.
- WSL-стенд: NVIDIA GeForce RTX 5060 Ti, 16311 MiB, Windows driver 610.88.
- Один и тот же код и зарегистрированный full-live сценарий через FreeSWITCH; на WSL peer зарегистрирован как `1003`, бот как `1002` и вызван через очередь `7100`.
- Одинаковые модели, RAG-индекс, входной WAV, PCMU/8000 mono, negotiated ptime 20 ms.
- XTTS-v2 работает с `stream_chunk_size=5`.
- Диалоговые паузы, VAD и TurnDetector для сравнения не менялись.
- Сценарий включает приветствие, связанные вопросы, barge-in, неизвестный ответ, подтверждение и перевод.

Это системный end-to-end тест двух стендов, а не изолированный тест вычислительной мощности GPU. На результат влияют CPU, диск, WSL, версии драйверов и совместное размещение моделей в VRAM.

## Результат full-live gate

Оба стенда прошли сценарий. Медианы рассчитаны по четырём ответам после LLM; min/max приведены по тем же четырём ответам. Начало измеряемой паузы — событие `pause_candidate` при обнаружении тишины после речи абонента; конец — `playback_first_frame` в PJMEDIA. Это пауза внутри телеметрии бота, а не измерение звука на ухе абонента. RTP и транзит FreeSWITCH в неё не включены.

| Метрика | A100 | RTX 5060 Ti | RTX относительно A100 |
|---|---:|---:|---:|
| Turn endpoint, медиана | 347,9 ms | 351,1 ms | +0,9% |
| Hard endpoint -> готовый текст LLM, медиана | 1109,4 ms | 2660,7 ms | +139,8% |
| Готовый текст LLM -> первый RTP audio frame, медиана | 199,9 ms | 137,8 ms | -31,1% |
| `pause_candidate` -> первый playback frame, медиана | 1664,5 ms | 3154,5 ms | +89,5% |
| Та же пауза, диапазон | 1536,1-1779,6 ms | 2641,4-6680,3 ms | — |
| XTTS adapter -> первый engine chunk, медиана | 184,7 ms | 119,7 ms | -35,2% |
| Answered-call window | 123,022 s | 123,330 s | +0,3% |

По каждому из четырёх ответов (в порядке поступления реплик; номера `turn_id` на стендах отличаются):

| Ответ | Стенд | `pause_candidate` -> hard endpoint | Hard endpoint -> LLM final | LLM final -> playback frame | Вся измеренная пауза |
|---:|---|---:|---:|---:|---:|
| 1 | A100 | 340,6 ms | 1005,5 ms | 206,9 ms | 1553,0 ms |
| 1 | RTX | 359,3 ms | 2487,8 ms | 155,1 ms | 3002,2 ms |
| 2 | A100 | 340,7 ms | 1022,0 ms | 173,5 ms | 1536,1 ms |
| 2 | RTX | 360,6 ms | 6205,2 ms | 114,5 ms | 6680,3 ms |
| 3 | A100 | 355,2 ms | 1227,9 ms | 193,0 ms | 1776,1 ms |
| 3 | RTX | 342,8 ms | 2154,9 ms | 143,7 ms | 2641,4 ms |
| 4 | A100 | 358,8 ms | 1196,9 ms | 223,8 ms | 1779,6 ms |
| 4 | RTX | 341,2 ms | 2833,7 ms | 131,9 ms | 3306,8 ms |

Участок `hard endpoint -> LLM final` включает завершение ASR, retrieval/embedding, формирование prompt и генерацию LLM. Его нельзя выдавать за чистое время inference Qwen.

## Изолированный XTTS sweep

Каждая строка состоит из десяти запусков. Оба стенда выбрали `chunk_size=5`, underrun и clipping отсутствуют.

| chunk_size | A100 TTFA median | RTX TTFA median | A100 full RTF median | RTX full RTF median |
|---:|---:|---:|---:|---:|
| 20 | 398,1 ms | 224,7 ms | 0,448 | 0,262 |
| 10 | 204,7 ms | 113,9 ms | 0,452 | 0,266 |
| 5 | 107,3 ms | 66,0 ms | 0,489 | 0,302 |

В изолированном TTS RTX 5060 Ti быстрее A100: при рабочем `chunk_size=5` медиана TTFA меньше на 38,5%, а full RTF — на 38,2%. Full-live trace подтверждает преимущество RTX на участке TTS, хотя абсолютные значения больше из-за совместной работы компонентов.

## Прогрев

Состояние кэшей отличалось, поэтому эти значения нельзя считать строгим GPU-бенчмарком:

- A100 evidence: 28,54 s суммарно;
- первый локальный WSL-проход после холодного состояния: 85,77 s, но звонок не состоялся из-за остановившегося Debian WSL;
- повторный WSL-проход с прогретыми Ollama/файловыми кэшами: 30,76 s.

Для пользовательской задержки используется только прогретый full-live участок: звонок начинается после readiness gate.

## Интерпретация

RTX 5060 Ti отлично выполняет XTTS и по этой операции быстрее тестовой A100. Узкое место локального полного контура находится до выдачи готового текста LLM: ASR, retrieval/embedding, LLM и их конкуренция за GPU.

После звонка `nvidia-smi` показывал около 9 GiB занятой VRAM из 16 GiB; Ollama держала процессы embedding и Qwen. Во время разговора к ним добавляются faster-whisper large-v3 и XTTS-v2. Поэтому возможная причина длинного и вариативного участка на RTX — дефицит VRAM и/или сериализация конкурирующей GPU-работы. Это гипотеза: данный прогон не содержит покадрового VRAM/CUDA trace и не атрибутирует занятую VRAM отдельным процессам.

Практический итог: RTX 5060 Ti пригодна для функционального демонстратора, но при текущем одновременном размещении всех выбранных моделей паузы ответа заметно хуже A100. Для приближения к A100 нужно отдельно оптимизировать основной `hard endpoint -> LLM final` путь: подобрать меньший ASR, управлять residency embedding/LLM, измерить GPU timeline и исключить конкуренцию с незавершённым TTS при barge-in.
